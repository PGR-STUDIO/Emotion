# REGISTRE DES PROJETS PGR

## Méthode

Ce registre regroupe les 57 conversations exportées par projet ou famille de projets. Les titres proches sont fusionnés dans un même groupe, tout en conservant les conversations originales comme traces. L’export ne fournit pas de marqueur fiable pour les conversations rayées ou supprimées : aucune conversation présente n’a donc été supprimée arbitrairement.

## PGR Studio et gouvernance

**Conversations regroupées :** Analyse et recommandations ; Création entreprise logiciels ; Architecture de gestion PGR ; Structuration administrative PGR ; Plan marketing PGR Studio ; Organisation des fichiers PGR ; Configurer une architecture unifiée.

**Fusion :** organisation, architecture et structuration sont traitées comme un même chantier de gouvernance PGR Studio.

**Points à suivre :** version de référence de l’architecture, emplacement des fichiers, rôle de chaque projet et prochaine étape unique.

## GitHub, dépôts et livraison

**Conversations regroupées :** Plan GitHub avec ChatGPT ; Connexion GitHub échouée ; Vérification des registres GitHub ; Analyse PR et CI ; Accès au registre PGR ; Accès GitHub Assistant.

**Problèmes relevés :** problèmes d’accès, de connexion et de validation des dépôts. Ce groupe doit rester séparé du développement fonctionnel.

## Solaire et photovoltaïque

**Conversations regroupées :** Logiciel de simulation solaire ; simulateur PV ; Base de Connaissances PV ; Base simulateur photovoltaïque ; Base concurrentielle Luma ; Base de données produits ; Audit V14 Simulateur.

**Versions repérées :** V10/V14 et versions intermédiaires du simulateur.

**Fusion :** le simulateur, les bases techniques, les produits et la concurrence sont liés mais doivent rester sous-projets distincts.

**Problèmes relevés :** données produits et prix à vérifier ; séparer les formules scientifiques, les références commerciales et l’interface du simulateur.

## Finance, budget et Cap Zéro Dette

**Conversations regroupées :** Amélioration simulateur crédits ; Analyse des dépenses mensuelles ; Lancement V10 Cap Zéro Dette ; Devis assurances ; Comparer toutes les assurances du foyer ; Rappels économies Bouygues et assurances.

**Versions repérées :** V10 et V14 de Cap Zéro Dette.

**Fusion :** crédits, échéanciers, assurances, dépenses et économies appartiennent au même domaine financier, mais doivent être documentés comme modules séparés.

**Problèmes relevés :** vérification nécessaire des calculs, des données familiales et des hypothèses budgétaires. Ne pas présenter le projet comme outil financier validé sans tests complets.

## PGR Health et sport

**Conversations regroupées :** Perdre du ventre rapidement ; Compilation PGR Health ; Évaluer programme personnalisé.

**Fusion :** programme sportif, perte de poids, suivi des progrès et adaptation personnalisée sont réunis sous PGR Health.

**Problèmes relevés :** séparer conseil général, suivi personnel et éventuelles données de santé. Le programme nécessite une validation humaine avant toute promesse médicale.

## Émotions, psychologie et santé mentale

**Conversations regroupées :** Trouver études scientifiques ; Améliorer la V018 ; Créer une IA psychologique ; Créer une roue des émotions ; Base scientifique émotionnelle.

**Versions repérées :** V0.18 et V0.22 apparaissent dans les échanges.

**Fusion :** application Émotion, roue, parcours, exercices et base scientifique constituent un même projet avec plusieurs composants.

**Problèmes relevés :** vérifier les études et exercices ; distinguer éducation émotionnelle, accompagnement et pratique clinique ; ne pas présenter le prototype comme dispositif thérapeutique.

## Agents IA et PGR-AI

**Conversations regroupées :** Création d’agent IA local ; Créer un agent IA ; Application mobile IA PGR ; Créer un agent IA polyvalent ; Gagner de l’argent IA ; Gagner de l’argent avec l’IA.

**Fusion :** les deux conversations sur les revenus IA sont des doublons thématiques ; les agents local, polyvalent et mobile sont des déclinaisons du même écosystème.

**Problèmes relevés :** plusieurs tests indiquent une tâche réussie alors qu’aucune modification de fichier n’est détectée. Il faut distinguer instruction, exécution, preuve et validation finale.

## Applications et outils

**Conversations regroupées :** Création application iPhone ; Créer une application PWA ; Logiciel Photobooth PGR ; Optimiseur de vacances ; Application lire pellicules en direct ; Scanner des photos ; Menu semaine famille.

**Fusion :** ces applications restent des projets distincts ; elles ne doivent pas être fusionnées techniquement, seulement indexées dans la même famille.

**Problèmes relevés :** niveau de maturité variable entre idée, prototype, code local et application testable.

## Création littéraire et graphique

**Conversation regroupée :** Avancer sur la saga.

**Versions et éléments :** tome 1, chapitres, relecture, artbook, couverture et éventuel projet BD/manga.

**Problèmes relevés :** conserver l’histoire de référence, distinguer les illustrations, l’artbook et le texte final.

## Vie pratique et achats

**Conversations regroupées :** Accès au site Promocash ; Conseils Ficus microcarpa ; Masquer la vue voisine ; Rocaille d’ombre conseils ; Trouver un plateau de coupe ; Meilleure eau pétillante.

**Statut :** demandes ponctuelles, à conserver dans un groupe séparé des produits PGR.

## Revenus et commercialisation

**Conversation regroupée :** Créer un revenu supplémentaire.

**Fusion :** à relier aux projets commercialisables, mais à ne pas confondre avec les prototypes déjà fonctionnels.

## Règle de versionnement proposée

Pour chaque projet : une version active, un historique des anciennes versions, une liste des défauts connus, les tests effectués, les fichiers de référence et la prochaine étape. Les anciennes versions restent archivées et ne servent pas de référence active.
